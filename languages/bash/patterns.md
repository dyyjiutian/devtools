# Bash 脚本结构模式

## 分层（Clean Architecture 思路）

```text
CLI 参数 / 交互界面 → 用例编排 → 系统、包管理器、网络、服务适配器
```

- 根 `setup.sh`：只做参数解析、模块选择、流程编排与 dry-run。
- 子目录 `setup.sh`：聚焦一个工具或一种环境能力。
- 发行版/包管理器差异收在适配函数里，不渗进高层流程。

## 幂等与托管配置

- 安装/配置脚本必须可重入：重复执行不重复追加、不破坏已正确状态。
- 改 shell rc、服务配置、编辑器配置前：用 marker / BEGIN-END 托管块、备份或等价策略。

## 预览与帮助

- 提供 `--help`。
- 有副作用时尽量提供 `--dry-run` / `--info-only` 或等价预览；日常验证优先预览，不跑真实安装。

## 复用优于复制

优先复用已有接口与 marker；避免跨模块粘贴同一段逻辑或引入隐式全局状态。
